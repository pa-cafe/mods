# PA Cafe Desktop

The one-paste installer opens a visible **PA Cafe** tab in Herdr. Use **PA Cafe Settings** in that tab to pair or change permissions. Your layout stays as it is.

## Install or update with one paste

The desktop mod is public in [pa-cafe/mods](https://github.com/pa-cafe/mods), so the commands need no GitHub account. They download only this folder of that repository. Quit **Herdr Desktop** before copying the mod; Herdr Core and already-running terminals can stay running.

**macOS / Linux (terminal)**

```bash
bash -c 'command -v git >/dev/null 2>&1 && git --version >/dev/null 2>&1 || { echo "PA Cafe: Install Git first: https://git-scm.com/downloads" >&2; exit 1; }; tmp=$(mktemp -d "${TMPDIR:-/tmp}/pacafe-install.XXXXXXXX") || exit 1; trap "rm -rf -- \"\$tmp\"" EXIT; git clone --depth 1 --filter=blob:none --sparse --single-branch --branch "${PACAFE_DESKTOP_REF:-main}" https://github.com/pa-cafe/mods.git "$tmp/repo" && git -C "$tmp/repo" sparse-checkout set connectors/herdr-desktop || { echo "PA Cafe: Download failed. Check the network connection, the branch name, and that Git is 2.25 or newer." >&2; exit 1; }; bash "$tmp/repo/connectors/herdr-desktop/install.sh" --open'
```

**Windows (PowerShell, with [Git for Windows](https://git-scm.com/install/windows))**

```powershell
& { $ErrorActionPreference = 'Stop'; $git = Get-Command git.exe -CommandType Application -ErrorAction SilentlyContinue | Select-Object -First 1; if (!$git) { throw 'PA Cafe: Install Git for Windows and enable Git on PATH: https://git-scm.com/install/windows' }; $execPath = & $git.Source --exec-path; if ($LASTEXITCODE -ne 0 -or !$execPath) { throw 'PA Cafe: Git for Windows is not working' }; $bash = Join-Path (Split-Path (Split-Path (Split-Path $execPath -Parent) -Parent) -Parent) 'bin\bash.exe'; if (!(Test-Path -LiteralPath $bash -PathType Leaf)) { throw 'PA Cafe: Git Bash not found. Install the full Git for Windows package.' }; $ref = if ($env:PACAFE_DESKTOP_REF) { $env:PACAFE_DESKTOP_REF } else { 'main' }; $tmp = Join-Path ([IO.Path]::GetTempPath()) ('pacafe-install-' + [guid]::NewGuid().ToString('N')); try { New-Item -ItemType Directory -Path $tmp | Out-Null; $repo = Join-Path $tmp 'repo'; & $git.Source clone --depth 1 --filter=blob:none --sparse --single-branch "--branch=$ref" https://github.com/pa-cafe/mods.git $repo; if ($LASTEXITCODE -eq 0) { & $git.Source -C $repo sparse-checkout set connectors/herdr-desktop }; if ($LASTEXITCODE -ne 0) { throw 'PA Cafe: Download failed. Check the network connection, the branch name, and that Git is 2.25 or newer.' }; & $bash ((Join-Path $repo 'connectors/herdr-desktop/install.sh').Replace('\','/')) --open; if ($LASTEXITCODE -ne 0) { throw "PA Cafe: Installer failed (exit $LASTEXITCODE)." } } finally { if (Test-Path -LiteralPath $tmp) { Remove-Item -LiteralPath $tmp -Recurse -Force } } }
```

The one-paste commands install from `main`; `PACAFE_DESKTOP_REF` can select another branch or known tag. They then open the existing PA Cafe tab or create one in a local Space. With no local Space, a visible Settings panel offers a native folder picker. Choose a folder to open an ordinary local Herdr Space and its PA Cafe tab, or cancel to leave your setup alone. The installer doesn't start an agent or pair automatically. If Desktop is not installed, install it first and run the command again (or `./install.sh --show` from an existing checkout).

The command checks Git before cloning and uses a temporary checkout. The installer copies only `pacafe-desktop/` into the `mods/` folder of `$HERDR_APP_HOME` when supplied, otherwise `$XDG_CONFIG_HOME/herdr-app` if set, otherwise `~/.config/herdr-app` (including Windows, where `~` is your user profile). It never changes a layout, pairing data, or other mods. If Desktop is present it runs an isolated native load check; a failed check does not install. If Desktop is missing, it says so and stages the mod files anyway. Missing Node.js or Herdr Core also prints a diagnostic. Install [Herdr Desktop](https://herdr.dev/app/) 0.1.18+ and [Node.js](https://nodejs.org/) 22+ before pairing; Node.js 18.17–21 can use slower polling. With an existing mod, the installer prints a backup path outside Herdr's scanned mods directory.

**Existing Git checkout of pa-cafe/mods:** in `connectors/herdr-desktop/`, `./install.sh` installs the checked-out Git commit, excluding working-tree edits, without opening Desktop. Add `--open` to install and open it or use `./install.sh --show` to open it without replacing files. Use `./install.sh --update` to fetch and install `origin/main` without changing the checkout, or `./install.sh --ref <commit-or-local-tag>` for rollback. On Windows run these inside Git Bash. An optional custom profile can be selected via `HERDR_APP_HOME` (in PowerShell, `$env:HERDR_APP_HOME = 'C:\Users\You\my-herdr-profile'` for that shell).

**Manual alternative:** copy only `pacafe-desktop/` to the profile's `mods/` directory. No layout is required. A previously installed `pacafe-main` layout is left alone.

1. Open **PA Cafe Settings** and check the address under **連線目標**. Choose **取得配對碼**, open the approval link, and approve it as the cafe owner after checking the code. Successful pairing opens a regular **PA Cafe** receiver tab in a local Space. If there is no local Space yet, open one first, then choose **啟動接收器** in Settings. Existing pairings can use the same button to resume after an update or restart.
2. In **派工權限**, open the **Spaces** or **Agents** multi-select to change its checkboxes, then click **套用權限**. Spaces default to included, so a newly discovered Space automatically joins for Agents you previously approved. Untick any Space you want to exclude, including with **清除** for all currently listed Spaces. Agents default to off; newly discovered Agents are not automatically approved. An existing approved Space's path or an existing launcher change still requires applying again. If automatic additions would exceed the 40-combination limit, existing approvals keep working until you narrow the selection.
3. Upgrading from the two-list picker retains its selected Agents and preserves exclusions for Spaces known at first discovery. The earlier per-Space permission matrix is not imported. Pairing and the connection target are not reset.
4. New tasks open in a regular Herdr tab in the approved Space. Settings only retain a manual-start shortcut for agents that cannot receive a starting prompt. In the phone, **Paired desktops** lets the owner revoke the connection.

## Tokscale usage preview

In the paired Desktop settings, **在本機預覽** shows the number of available history days and fresh quota accounts. Nothing is sent, and the preview does not open the Tokscale upload login. **上傳至配對小屋** is a separate, one-shot action. It reuses the existing PA Cafe upload login only if it is bound to the same origin and the server explicitly verifies that the token belongs to the paired house's owner; older servers cannot receive these uploads. This does not create a token, change an existing login or install/schedule a job. History and quota are separate results and one may be unavailable while the other succeeds.

- History uses a small native scanner linked directly against the pinned dnplus Tokscale Core Rust crate, not the Tokscale CLI. This preview reads local **Codex and Claude Code** history. It sends daily/client/model token aggregates, estimated cached-price floors, and the existing Tokscale device ID, not prompts, sessions, paths, command lines, or credentials in the payload. It does not contact provider APIs. An upload requires an existing device ID and pinned reporting time zone and refuses a conflicting device ID override; it never mints a new source. Without a previously pinned reporting time zone, local history preview is provisional and only fresh quota can be uploaded. Do not guess a time zone for an existing device: changing date buckets can duplicate prior usage. The existing Tokscale autosubmit must already be disabled; the mod won't turn it off itself.
- Quota only accepts valid, at most five-minute-old **Codex / Claude** observations already present in the Tokscale subscription cache. It strips raw emails, account labels and diagnostics and preserves the identity used by the existing quota endpoint. Unknown, stale or unavailable observations do not become zeroes. The mod does not yet refresh provider quota or replace all standalone Tokscale workflows.
- The usage tool is optional. From a trusted checkout, run `./install.sh --with-usage` to explicitly build and add the scanner at the selected commit; the default install never builds or runs it. This needs an installed Rust 2024/Cargo toolchain, and downloading pinned build dependencies can require network access. Use the same option on updates if you want to keep the scanner. No executable is committed, and installing the optional tool does not scan or upload anything. If the helper is absent, Settings explains how to enable it. macOS packaging is verified; Windows packaging has not been exercised end to end. An OS advisory lock prevents overlapping manual runs and releases after a forced quit.

## When dispatch runs

Keep the PA Cafe receiver tab open. After it has been shown once, Herdr keeps it running in the background while you use other tabs or Spaces, close Settings, or hide the sidebar. Settings shows whether it is receiving; the receiver tab has a shortcut back to Settings. **啟動接收器** reopens an existing local receiver tab, even if it was in another Space, instead of creating another copy. On a full app restart, Herdr starts only the shown views: select the receiver tab once if it isn't shown already (or use **啟動接收器**). Closing that tab or quitting Herdr stops new dispatches unless an existing mounted sidebar receiver takes over. Herdr Core may keep already-launched terminal sessions running.

Already added PA Cafe to a personal sidebar? Keep your existing block; it works without the receiver tab, and an open tab and sidebar share one bridge in the window. For an optional dock in a personal layout, append only the block with content `{"mod":"pacafe-desktop","props":{"role":"sidebar"}}`, an unused block ID and a 32 px size to your chosen sidebar children. Do not replace the layout. Herdr does not add structural blocks to shipped layouts, so use the receiver tab with the standard layout.

Accepted work is queued on the cafe for up to five minutes if the device disconnects before claiming it; a timely reconnect can pick it back up. A work item that expires before claim is marked not started, not silently relaunched. Offline profiles cannot accept new work. On a compatible cafe an already-queued item stays pending while its still-approved profile is offline; removing that profile revokes it. Older cafes do not distinguish an offline profile from a removed one.

With Node.js 22 or newer and a compatible cafe, an idle desktop waits for notifications without polling the cafe, including finished sessions open for follow-up. Local terminal status changes trigger a fresh sync. A brief socket message tells it to check the durable queue; the message contains no task or terminal data. A sleeping computer cannot receive a dispatch until Herdr reconnects. Running sessions still synchronize their input/status lease, and screen content is read only while the owner opens the terminal. Older cafes or Node versions without WebSocket support use periodic polling.

On macOS, **保持待命** is off by default. Turn it on in PA Cafe Settings to hold a short, power-adapter-only system sleep assertion while the paired receiver runs. The display may turn off. Turning it off or quitting stops renewal; the last assertion expires within 12 seconds. It cannot wake a sleeping Mac or override lid-closed sleep.

Pairing credentials, approvals, and session metadata stay in private files tied to that pairing. Prompts for manually started agents are available for the lifetime of the receiver.

The mod starts a dedicated Core terminal in the approved workspace folder. Codex and Claude Code report completion through Core's root agent status and keep their regular approval prompts, except that a team lead may run Herdr's `hc` (below). Other supported agents, OpenCode included, open with their default local command and the prompt is displayed in settings for manual start.

### Teams

When the cafe stores helpers (its sync answer says `teammates: true`), a Claude Code or Codex agent leads the task and may start helpers with Herdr's own `hc run`, on the approved Claude Code, Codex and OpenCode profiles for the same machine, Space and folder. Older cafes get no team; the agent works alone, as before.

**The lead can operate every terminal in this computer's Herdr.** `hc` has no per-terminal permission, so only the lead's brief keeps it to its own helpers, and it can also start other programs through Core. Approve a Space and agent for dispatch only if you accept that; the dispatch settings say so too.

- A Claude Code lead runs with `--permission-mode default --allowedTools "Bash(hc:*)"`. A Codex lead (0.172 or newer) keeps its workspace sandbox, and its network reaches only Core's socket; an older Codex works alone.
- Helpers keep their own approval prompts: Claude Code may only `hc send` its report without asking, Codex runs in the workspace sandbox with no network (so it cannot reach Core, and the lead reads its screen), and OpenCode runs with the barista's own OpenCode settings.
- The lead may answer a helper's prompt only for work inside the task folder and hands everything else back in its reply. A helper's prompt cannot be answered from the phone.
- The brief asks for at most three helpers; the mod does not enforce that number. The cafe stores up to twelve.
- The cafe keeps each helper's name (chosen by the lead), CLI name, Herdr status word and parent name under the task. Screens, prompts and paths are not sent.

The cafe owner can view the screen of a live PA Cafe agent in its approved workspace. Codex and Claude Code receive plain PA Cafe messages, including line breaks and leading punctuation, when Herdr can verify the running agent and its status. Shortcuts, shell modes, questions and sign-in prompts require the desktop. In the PA Cafe receiver tab, **需要你處理** lists local Codex and Claude Code terminals whose agent is waiting, and **開啟本機終端** focuses that already attached terminal. It sends no keys; answer the prompt there. A terminal kept in the main window takes follow-up text while it reports idle or working. Other supported agents allow viewing and take input on the desktop. PA Cafe relays the current screen in memory while the terminal is open. Message bodies expire in memory, and terminal content stays out of push notifications.

With a compatible cafe, the owner can also approve or deny a permission request from the phone. The phone shows the agent's own one-line summary, not the dialog: Claude Code writes `approve <Tool>: <what>`, folds a long command and names only the path of a file edit. Only a summary that names one tool call is offered, at most 500 characters with no invisible format characters such as bidi overrides. A bare label (Claude Code sends `permission prompt` when its summary would be cut), a summary that names only the tool, and dialogs whose first option approves more than one request (the plan dialog, plan mode, browser or computer use) stay on the desktop. Codex 0.172 reports no request text, so its requests stay on the desktop too. The mod sends the summary to the cafe while it waits, with the pairing secret removed. When the owner answers, the mod reads the dialog and the status again over one Core connection and presses one key only if the same request is still waiting. To approve, the option the key picks must read exactly as the once-only Yes: `1. Yes` for Claude Code (key `1`), `Yes, proceed (y)` for Codex (key `y`); anything else is left alone. Esc declines. The mod never answers on its own. Herdr Core has no check for a waiting prompt at the moment it presses: it holds a key until nobody has typed in that terminal for 3 seconds and presses it even after the connection closes, and its reply names the status and turn but not which request. So if someone answers at the desk while a phone answer is on its way, the key can land on the next request. A key Core held back is reported as possibly not delivered, never as sent. If the request is still showing a few seconds after the key, the phone and the receiver also say the answer may not have arrived. The cafe can turn phone answers off for every desktop without a mod update.

With a compatible cafe, scrolling up in the terminal requests older output for a paired, live local Codex or Claude Code session on macOS or Linux. The current screen still updates independently. History is read only when explicitly requested and when the same approved terminal reports idle or done. A full-screen program may briefly scroll while Herdr Core reads it and restores its view. Each read is limited to 10,000 lines and 512 KiB; the available scrollback can be shorter or unavailable, including after a terminal closes or when the agent keeps its own history. The mod sends pages of at most 16,000 characters, keeps the snapshot in local memory for up to three minutes, and does not save it to disk.

A paired, supported local Claude Code or Codex session can receive one private attachment of up to 256 KiB with a text follow-up. The file is delivered beside the terminal, not added to a project or committed. New supported local Claude Code and Codex sessions dispatched by PA Cafe return only their final reply to the paired cafe owner by default. Existing sessions are not backfilled. No terminal screen or complete transcript is uploaded by this feature.

On a supported Codex CLI (hook discovery verified on 0.172.0), open `/hooks` in the actual terminal and review the PA Cafe `UserPromptSubmit` and `Stop` entries under Codex's native trust rules. The commands remain the same across dispatches from the same mod installation; a changed hook or mod path may need review again. Capture uses Codex without the shared daemon so the hooks inherit the correct Herdr terminal environment. The first trusted prompt pins the conversation; final responses from unrelated threads are not sent. The mod does not approve the hooks, read a Codex transcript, or upload earlier replies.

The connection target defaults to `https://pacafe.dnplus.dev`. For an isolated PA Cafe Worker, choose **變更網址** and enter `http://127.0.0.1:<port>`. To prefill it in a fresh test profile, set `PACAFE_DESKTOP_ORIGIN` before starting Herdr. Use a separate `HERDR_APP_HOME`, Core socket and Core state directory with synthetic workspaces and credentials for testing. Give the isolated instance a short `HC_SESSION` and a short socket path on macOS.

### Where dispatched work appears

New PA Cafe tasks appear under a dedicated **PA Cafe** Space on the approved Herdr Core. They do not switch the Space or tab you're currently using. An approved remote Core gets its own Space; Herdr does not mix machines in one Space. Existing sessions stay wherever they were opened, and an existing Space called “PA Cafe” is not taken over.

Each task still starts in the exact selected, approved folder. PA Cafe Settings in Herdr shows the full folder path locally. The cafe receives profile display names, not your absolute paths. The generated Space is not an additional folder permission.
